## Платежи: установленные ограничения

Проверена среда основного процесса API, а не отдельного `docker exec`: entrypoint создаёт secret files и меняет environment. Значения секретов не выводились.

- `ARCO_PAY_PROVIDER_MODE=disabled`; отсутствуют API key file, bearer token file, shop ID, public key file проверки callback.
- SIH catalog, SIH Steam refill и SMTP secret files доступны процессу.
- Commerce feature flags выключены. Их включение само по себе не настроит merchant и не докажет оплату.
- Пользователю задан вопрос о защищённом расположении боевой конфигурации именно магазина Gems. Секреты соседних проектов не переносились.
- Для реальной приёмки также нужны согласованные получатель Steam/trade token и сумма. Эти acceptance-параметры не являются дефектами пользовательской формы.

Локальные интеграционные тесты проверяют quote → session → hosted checkout, привязку суммы/магазина/операции, подпись callback, повтор callback и reconciliation, однократное зачисление и отдельный Steam flow без изменения Gems wallet. Они используют тестовые провайдеры и не доказывают боевую оплату.

## Выполненные проверки

- Backend unit: 254 passed.
- PostgreSQL integration: 167 passed, 1 skipped (внешняя SIH acceptance без реквизитов). Только локальная `gems_test` через `GEMS_TEST_DATABASE_URL`.
- Первоначальный отдельный запуск каталога получил `socket hang up`; полный повтор прошёл все 13 тестов каталога.
- Сравнение/бюджет/избранное: включены в полный Playwright; проверены ошибки, таймаут, повтор, пагинация, пустая SSR, смена оружия/категории, быстрые суммы, ползунок, поздние ответы и сохранение избранного.
- RED интерфейсных проверок подтверждён: цвет, email login, подпись корзины, отступ 0 px вместо >=16 и disabled payment label.
- `npm run verify`: backend 254, frontend 69; lint/typecheck/build/OpenAPI зелёные; 831 дизайнерский файл без изменений.
- Независимое read-only ревью выявило два случая сравнения: список оружия зависел от SSR и повтор мог потерять клиентскую пару. Оба воспроизведены RED тестами и исправлены.
- Список оружия загружается отдельно из опубликованной CS2 номенклатуры; наличие проверяется при получении вариантов. Это может дать честный пустой результат для временно недоступного оружия, без тяжёлого подсчёта предложений на главной.
- Первая полная браузерная проверка: 81 passed, 1 ошибка неоднозначного селектора теста быстрых сумм; селектор уточнён. Итоговый прогон после исправлений ревью: **86 passed**.
- Визуально просмотрены снимки Steam-only входа на desktop и подтверждения почты на mobile: кнопки и отступы соответствуют требованиям.
- Production проверка после публикации остаётся отдельным этапом.

VV-171 не считается полностью закрытой до устранения ограничений пункта 10 и отдельного подтверждения реального платежного результата.
