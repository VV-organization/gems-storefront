# Реальная приёмка провайдеров

Локальные интеграционные тесты используют настоящую PostgreSQL, но подменяют SIH/платёжные HTTP-ответы. Browser suite использует явный тестовый сервер и перехватывает API. Это не доказывает оплату, зачисление или выдачу в production.

Перед реальным прогоном нужны собственные Gems merchant, ключи SIH с правом трёх игр, SMTP, получатель Steam и торговая ссылка, согласованные суммы. Локально из `backend/` команда `node --env-file=.env --import tsx src/provider-acceptance-readiness.ts` проверяет наличие конфигурации без вывода секретов. В server Compose с временно скопированным env из [deployment](deployment.md) выполнить `docker compose run --rm --no-deps api node dist/provider-acceptance-readiness.js`: entrypoint подготовит `*_FILE` из runtime env. Обе команды не выполняют платежи. Ready означает наличие настроек, а не успешную реальную операцию.

Для каждой проверки сохранить идентификаторы Gems order/payment, provider order/customId, итоговый статус, время и результат сверки ledger/hold. Не записывать торговые токены, cookies, ключи или полный webhook в отчёт.

- Gems: 1 000 Gems → 500 ₽; checkout открыт → платёж действительно подтверждён провайдером → ровно одно ledger credit. Повтор webhook и повтор status-check не должны менять баланс повторно.
- CS2, Rust, TF2: отдельная покупка каждой игры, затем смешанная корзина. AppId соответственно 730, 252490, 440. Сопоставить состав quote, immutable snapshot, provider terminal status, hold settlement и историю. Отдельно проверить частичную выдачу и возврат неиспользованного резерва.
- Steam: логин + email, 1 000 ₽ зачисления + 50 ₽ комиссии. Проверить captured payment и фактическое пополнение Steam отдельно. Баланс Gems не изменяется. После OTP история гостевого платежа появляется у проверенного владельца email.
- Возврат с оплаты с `payment=success` при ещё pending статусе не показывает успех. После 15 минут повторное открытие требует серверной проверки canPay. Timeout после создания восстанавливается тем же ключом, новая попытка создаётся только после определённого результата.

Проверка реального login, платежей, выдачи и email доставки остаётся обязательной перед релизом. Локальные прогоны не расходовали деньги и не создавали SIH заказы.
